Laboratuvar düzeni

Bu uygulamada iki sistem kullanılır. Windows (ana bilgisayar), izlenecek sistemdir; buraya Wazuh agent kuracağız. Wazuh sanal makinesi (.ova dosyasından içe aktarılan hazır sunucu) ise logları toplar, analiz eder ve web arayüzünü sunar. Bilgisayardaki Kali Linux sanal makinesi bu uygulamada kullanılmaz; açıksa kapatın.

Agent, Windows'ta olan biteni (oturum açmalar, dosya değişiklikleri, ayarlar) toplayıp sunucuya gönderir. Sunucu bu kayıtları kurallarla karşılaştırır ve şüpheli olanları alarma çevirir. Bu yüzden iki makinenin bu üç port üzerinden birbirine ulaşabilmesi şarttır.

Bölüm 0: Başlamadan önce kontroller

Adım 0.1 Wazuh sanal makinesini başlatın, oturum açın ve servisleri kontrol edin.

VirtualBox/VMware'de Wazuh sanal makinesini başlatın. Açılan siyah konsol ekranında kullanıcı adı wazuh-user, parola wazuh ile giriş yapın.

Konsolun klavye düzeni İngilizcedir (US), bu yüzden Türkçe klavyede bazı tuşlar farklı karakter yazar. Giriş yaptıktan sonra önce klavyeyi Türkçeye çevirin:

sudo loadkeys trq

Komut çalışmazsa şu tuşları kullanın: - için 0'ın sağındaki * tuşu, _ için Shift + *, / için sağ Shift'in solundaki . tuşu, = için Backspace'in solundaki - tuşu.

Wazuh sanal makinesi konsolu
sudo systemctl is-active wazuh-manager wazuh-indexer wazuh-dashboard

Alt alta üç kez active yazar.

Wazuh OVA dosyası, sunucunun tüm parçaları önceden kurulmuş hazır bir sanal makinedir. Wazuh üç parçadan oluşur. Manager logları analiz eder, Indexer alarmları saklar ve aranabilir yapar, Dashboard ise tarayıcıdan gördüğümüz arayüzdür. Biri çalışmazsa ya agent bağlanamaz ya da arayüz boş görünür. Sanal makine yeni açıldıysa servislerin tam kalkması 2–3 dakika sürebilir.

Çalışmayan servis varsa: sudo systemctl restart wazuh-indexer wazuh-manager wazuh-dashboard

Adım 0.2 Wazuh sanal makinesinin IP adresini ve sürümünü öğrenin.
Wazuh sanal makinesi konsolu
ip -4 addr show
sudo /var/ossec/bin/wazuh-control info
Wazuh sunucu IP adresi___.___.___.___
Wazuh sürümüv4.___.___

IP adresi lo dışındaki ağ kartının (ör. eth0) inet satırındadır; 127.0.0.1 değildir. Agent'a "logları kime göndereceğini" bu IP ile söyleyeceğiz. Sürümü not ediyoruz, çünkü agent sürümü sunucu sürümünden yeni olamaz; yeni bir agent eski bir sunucuya bağlanamaz.

Adım 0.3 Güvenlik duvarının portları engellemediğini kontrol edin.
Wazuh sanal makinesi konsolu
sudo systemctl is-active firewalld

inactive (ya da "Unit not found") yazar. Bu durumda bir şey yapmanıza gerek yoktur.

active yazıyorsa portları açın:

sudo firewall-cmd --permanent --add-port=443/tcp
sudo firewall-cmd --permanent --add-port=1514/tcp
sudo firewall-cmd --permanent --add-port=1515/tcp
sudo firewall-cmd --reload

Wazuh OVA sanal makinesi Ubuntu değil, Amazon Linux tabanlıdır; bu yüzden ufw yerine firewalld kullanılır. Güvenlik duvarı bu portları engellerse Windows'taki agent sunucuya ulaşamaz.

Adım 0.4 Windows'tan sunucuya erişimi test edin.
Windows PowerShell
Test-NetConnection 192.168.56.101 -Port 1514
Test-NetConnection 192.168.56.101 -Port 1515
Test-NetConnection 192.168.56.101 -Port 443

IP yerine Adım 0.2'de not ettiğiniz adresi yazın.

Üç testte de TcpTestSucceeded : True yazar.

Kuruluma geçmeden ağ yolunun açık olduğundan emin oluyoruz. Kitaptaki uygulamada en sık yaşanan "agent kuruldu ama listede görünmüyor" sorununun nedeni neredeyse her zaman budur.

False çıkıyorsa sorun büyük olasılıkla sanal makinenin ağ ayarıdır. VirtualBox'ta ağ bağdaştırıcısı NAT ise Windows sanal makineye ulaşamaz; ayar Köprü (Bridged) ya da Host-only yapılmalıdır. Ayar değişince sanal makineyi yeniden başlatın ve Adım 0.2'deki IP adresini tekrar okuyun, çünkü adres değişir.

Uygulama 1: Windows'a Wazuh agent kurulumu

Adım 1 Wazuh web arayüzüne giriş yapın.

Windows'ta tarayıcıyı açın ve adres çubuğuna https://<sunucu-IP> yazın. Kullanıcı adı admin, parola admin.

"Bağlantınız gizli değil" uyarısı çıkarsa Gelişmiş → Siteye ilerle seçeneğiyle devam edin.

Wazuh kurulumda kendi imzaladığı (self-signed) bir sertifika üretir. Bağlantı yine şifrelidir, ancak sertifika tanınmış bir kuruluşça imzalanmadığı için tarayıcı uyarı verir. Laboratuvar ortamında bu normaldir.

Adım 2 Agent yönetim ekranını açın.

Sol üstteki ☰ menü simgesine tıklayın ve Agents management → Summary yolunu izleyin. Sayfa başlığı Endpoints olarak görünebilir.

Kitaptaki Wazuh → Agents menüsü, Wazuh 4.8 ve sonrasında bu yeni menüyle değiştirilmiştir.

Bu ekran sunucuya kayıtlı tüm agent'ları ve durumlarını (Active, Disconnected, Pending, Never connected) gösterir. Kurulumdan sonra agent'ımızın burada Active görünmesi başarının kanıtı olacak.

Adım 3 Deploy new agent düğmesine tıklayın.

Wazuh, seçtiğimiz bilgilere göre kurulum komutunu kendisi üretir. Böylece doğru sürümü, doğru sunucu adresini ve doğru parametreleri elle yazmak zorunda kalmayız.

Adım 4 İşletim sistemi paketini seçin.

WINDOWS kartında MSI 32/64 bits seçeneğini işaretleyin.

Kitapta yer alan "Windows XP / Windows 7+" sürüm seçimi ve ayrı mimari adımı yeni arayüzde kaldırılmıştır. Tek MSI paketi hem 32 hem 64 bit Windows'a kurulur.

Adım 5 Sunucu adresini ve agent adını girin.

Server address kutusuna Wazuh sanal makinesinin IP adresini (Adım 0.2) yazın. Optional settings bölümünde Assign an agent name alanına benzersiz bir ad verin (örnek: PC07-AYILMAZ). Grup olarak default kalsın.

Agent adı, sunucunun bu bilgisayarı diğerlerinden ayırt etmesini sağlar ve kayıttan sonra değiştirilemez. Aynı ad iki kez kullanılırsa ikinci kayıt reddedilir. Türkçe karakter ve boşluk kullanmayın; yalnızca harf, rakam, - ve _ güvenlidir.

Adım 6 PowerShell'i yönetici olarak açın.

Başlat simgesine sağ tıklayın ve Terminal (Yönetici) ya da Windows PowerShell (Yönetici) seçeneğini seçin. Açılan pencerenin başlığında Yönetici / Administrator yazdığını kontrol edin.

Agent bir Windows hizmeti olarak kurulur, C:\Program Files (x86) altına yazılır ve güvenlik olay günlüklerini okur. Bu üç işlemin üçü de yönetici yetkisi ister. Normal yetkiyle çalıştırılan komut hata vermeden yarıda kalabilir.

Adım 7 Arayüzün ürettiği kurulum komutunu kopyalayıp PowerShell'e yapıştırın ve çalıştırın.

Komut aşağıdakine benzer olacaktır. Kendiniz yazmayın, arayüzden kopyalayın.

Invoke-WebRequest -Uri https://packages.wazuh.com/4.x/windows/wazuh-agent-4.X.X-1.msi -OutFile $env:tmp\wazuh-agent; msiexec.exe /i $env:tmp\wazuh-agent /q WAZUH_MANAGER='192.168.56.101' WAZUH_AGENT_NAME='PC07-AYILMAZ'

Komut iki iş yapar. Invoke-WebRequest kurulum paketini (MSI) Wazuh sitesinden indirir. msiexec /q ise paketi sessizce (pencere açmadan) kurar ve WAZUH_MANAGER ile WAZUH_AGENT_NAME değerlerini doğrudan agent ayarlarına yazar. Bu sayede kurulum biter bitmez agent sunucuyu tanır.

Okul ağı internete çıkışı engelliyorsa indirme başarısız olur. Bu durumda C:\Lab klasörüne önceden kopyalanmış MSI dosyasıyla kurun:

msiexec.exe /i C:\Lab\wazuh-agent-4.X.X-1.msi /q WAZUH_MANAGER='192.168.56.101' WAZUH_AGENT_NAME='PC07-AYILMAZ'
Adım 8 Agent hizmetini başlatın ve durumunu kontrol edin.
NET START Wazuh
Get-Service WazuhSvc

"Wazuh hizmeti başarıyla başlatıldı" mesajı görünür ve Get-Service çıktısında Status sütunu Running olur.

Kurulum hizmeti yalnızca oluşturur, çalıştırmaz. Hizmet başladığı anda agent sunucuya bağlanır, 1515 portundan kaydını yapar ve 1514 portundan log göndermeye başlar. Kitaptaki "bilgisayarı yeniden başlatın" adımına gerek yoktur.

Adım 9 Agent'ın arayüzde göründüğünü doğrulayın.

Tarayıcıda Agents management → Summary ekranına dönün ve Refresh düğmesine basın.

Agent listesinde kendi agent adınız, Windows sürümünüz ve active durumu görünür.

Get-Content "C:\Program Files (x86)\ossec-agent\ossec.log" -Tail 25

Alternatif yöntem (kitaptaki 10. Adım): C:\Program Files (x86)\ossec-agent\win32ui.exe dosyasını yönetici olarak çalıştırın. Açılan Wazuh Agent Manager penceresinde Manager IP alanına sunucu adresini yazın, Save ile kaydedin ve Manage → Restart ile hizmeti yeniden başlatın. Yeni sürümlerde Authentication key alanını elle doldurmanız gerekmez; agent ilk bağlantıda anahtarı otomatik alır.

Uygulama 2: Agent'tan gelen güvenlik olaylarını izleme

Adım 1 Agent'ın özet ekranını açın.

Agents management → Summary listesinde kendi agent adınıza tıklayın.

Bu ekran tek bir bilgisayarın güvenlik özetidir: MITRE ATT&CK taktikleri, uyumluluk (Compliance) dağılımı, son dosya bütünlüğü olayları ve son yapılandırma taraması. Yönetici çok sayıda makine arasından sorunlu olana buradan odaklanır.

Adım 2 Güvenlik olayları ekranını açın.

☰ → Threat intelligence → Threat Hunting yolunu izleyin. Üst kısımdaki agent seçiciden kendi agent'ınızı seçin.

Kitaptaki More → Security events ekranının yeni adı Threat Hunting'dir. Dashboard sekmesi grafikleri, Events sekmesi olay listesini gösterir.

Kurulumdan bu yana gelen tüm alarmlar burada toplanır. Dashboard sekmesindeki Total, Level 12 or above alerts, Authentication failure ve Authentication success sayaçları sistemin genel durumunu tek bakışta özetler.

TotalLevel 12 or aboveAuthentication failureAuthentication success
    
Adım 3 Events sekmesinde olay listesini inceleyin.

Listede her satır bir alarmdır. Şu sütunlara dikkat edin: rule.description (ne oldu), rule.level (önem seviyesi, 0–15), rule.id (hangi kural tetiklendi) ve rule.mitre.id (MITRE ATT&CK teknik kodu).

Seviye ne kadar yüksekse olay o kadar önemlidir. 3 gibi düşük seviyeler bilgilendirme amaçlıdır (ör. başarılı oturum açma); 10 ve üstü dikkat ister; 12 ve üstü genellikle acil incelenmesi gereken olaylardır. Kural ID'si ise aynı türdeki olayları filtrelemeyi kolaylaştırır.

2-A: Başarısız oturum açma olayı oluşturma

Adım 4 Windows'ta oturum açma denetiminin açık olduğunu doğrulayın.
Windows PowerShell (Yönetici)
auditpol /get /subcategory:"{0CCE9215-69AE-11D9-BED3-505054503030}"

Çıktıda Başarı ve Hata (Success and Failure) yazar.

Yalnızca "Başarı" yazıyorsa açın: auditpol /set /subcategory:"{0CCE9215-69AE-11D9-BED3-505054503030}" /success:enable /failure:enable

Windows bir olayı denetleme ilkesi açık değilse hiç kaydetmez; kaydedilmeyen bir olayı da Wazuh göremez. Komutta alt kategorinin adı yerine kimliği (GUID) kullanıyoruz, çünkü Türkçe Windows'ta kategori adları Türkçedir ve İngilizce adla verilen komut hata verir.

Adım 5 Bilerek yanlış parola girin.

Windows + L tuşlarıyla ekranı kilitleyin. Kendi kullanıcınız için 3 kez yanlış parola girin, ardından doğru parolayla oturum açın.

Windows her başarısız denemeyi Güvenlik günlüğüne Olay Kimliği 4625 olarak yazar. Agent bu kaydı okuyup sunucuya gönderir, sunucu da kuralla eşleştirip alarm üretir. Böylece gerçek bir parola deneme saldırısının ilk izlerini güvenli biçimde görmüş oluruz.

Adım 6 Oluşan alarmı bulun ve inceleyin.

Threat Hunting → Events sekmesine dönün. Arama çubuğuna rule.id:60122 yazıp Enter'a basın. Bir alarm satırının solundaki oka tıklayarak ayrıntılarını açın.

Logon failure - Unknown user or bad password açıklamalı, seviyesi 5 olan alarmlar görünür. Ardından gelen başarılı oturum açma da Windows logon success (kural 60106) olarak listelenir.

Ayrıntı ekranında hangi kullanıcı adıyla, hangi bilgisayardan ve hangi oturum türüyle deneme yapıldığı görülür (data.win.eventdata.targetUserName, data.win.system.eventID). Saldırı incelemesinde ilk sorulan soru "kim, ne zaman, nereden?"dir ve bu alanlar o soruyu yanıtlar.

Kısa sürede çok sayıda başarısız deneme yapılırsa Wazuh tekil alarmların yanında daha yüksek seviyeli ayrı bir çoklu başarısız oturum alarmı üretir. Bu, parola deneme (brute force) saldırısının tespit edilme biçimidir.

2-B: Dosya bütünlüğü izleme (FIM)

Adım 7 İzlenecek bir test klasörü oluşturun.
Windows PowerShell (Yönetici)
New-Item -ItemType Directory -Path C:\LabFIM

Windows agent'ı varsayılan olarak C:\Windows\System32 gibi sistem klasörlerini izler; Masaüstü veya İndirilenler gibi kullanıcı klasörlerini izlemez. Kitaptaki 6. Adım'da bu ayar anlatılmadığı için dosya işlemleri alarm üretmeyebilir. Bu yüzden izlenecek klasörü kendimiz tanımlıyoruz.

Adım 8 Klasörü agent ayarlarına ekleyin.

Not Defteri'ni yönetici olarak açın ve C:\Program Files (x86)\ossec-agent\ossec.conf dosyasını açın. <syscheck> bölümünü bulun ve içine aşağıdaki satırı ekleyin:

<directories realtime="yes" check_all="yes">C:\LabFIM</directories>

Dosyayı kaydedin, ardından agent'ı yeniden başlatın:

Restart-Service WazuhSvc

realtime="yes" olmadan agent klasörü yalnızca periyodik taramada (varsayılan olarak 12 saatte bir) kontrol eder. Gerçek zamanlı izleme açıldığında her değişiklik anında bildirilir. check_all="yes" ise boyut, sahip, izinler ve özet (hash) değerlerinin hepsinin karşılaştırılmasını sağlar. Agent ayar dosyasını yalnızca başlarken okuduğu için yeniden başlatma şarttır.

Etiketleri yazarken tırnak ve açılı ayraçlara dikkat edin. Hatalı bir ossec.conf dosyası agent'ın hiç başlamamasına neden olur. Böyle olursa hata satırını ossec.log dosyasında görürsünüz.

Adım 9 Dosya oluşturun, değiştirin ve silin.

Agent yeniden başladıktan sonra yaklaşık 30 saniye bekleyin, ardından komutları arada 10–15 saniye bırakarak sırayla çalıştırın:

Set-Content C:\LabFIM\gizli.txt "ilk icerik"
Add-Content C:\LabFIM\gizli.txt "yetkisiz degisiklik"
Remove-Item C:\LabFIM\gizli.txt

Bekleme, agent'ın ilk taramayı bitirip klasörün "temiz" hâlini (baseline) kaydetmesi içindir. FIM her değişikliği bu ilk hâlle karşılaştırarak tespit eder. Saldırganlar sisteme girdikten sonra genellikle dosya bırakır, ayar dosyalarını değiştirir ya da izlerini silmek için kayıtları siler. FIM bu üç davranışı da yakalar.

Adım 10 FIM alarmlarını inceleyin.

☰ → Endpoint security → File Integrity Monitoring yolunu izleyin, agent'ınızı seçin ve Events sekmesine geçin.

Üç alarm görünür: File added to the system (554), Integrity checksum changed (550) ve File deleted (553).

"Değiştirildi" alarmının ayrıntısında dosyanın eski ve yeni özet (MD5/SHA1/SHA256) değerleri yan yana görülür. Özet değerinin değişmesi, içeriğin değiştiğinin kesin kanıtıdır.

2-C: Güvenlik yapılandırma denetimi (CIS kontrolleri)

Adım 11 CIS tarama sonuçlarını açın.

☰ → Endpoint security → Configuration Assessment yolunu izleyin ve agent'ınızı seçin. Listedeki CIS Microsoft Windows 10/11 ... Benchmark politikasına tıklayın.

Kitaptaki "SCA" modülünün yeni adı Configuration Assessment'tır. Agent ilk başladığında taramayı otomatik yapar; sonuç görünmüyorsa birkaç dakika bekleyip sayfayı yenileyin.

CIS (Center for Internet Security) kıyaslamaları, bir işletim sisteminin güvenli kabul edilmesi için hangi ayarların nasıl olması gerektiğini listeleyen uluslararası rehberlerdir. Wazuh her maddeyi bilgisayardaki gerçek ayarla karşılaştırır ve Passed / Failed / Not applicable olarak işaretler. Bu ekran, sistemin saldırıya ne kadar açık yapılandırıldığını ölçer.

PassedFailedNot applicableScore (%)
    
Adım 12 Başarısız bir kontrolü inceleyin.

Sonuç sütununda Failed yazan bir satıra tıklayın. Açılan ayrıntıda Rationale (neden önemli), Remediation (nasıl düzeltilir) ve Checks (Wazuh'un neyi kontrol ettiği) bölümlerini okuyun.

Kontrol başlığı 
 
Neden önemli? (kendi cümlenizle) 
 
Nasıl düzeltilir? 
 

Tespit sistemi yalnızca alarm vermez, açıkların nasıl kapatılacağını da gösterir. Bir yönetici bu listeyi kullanarak sistemi adım adım sertleştirir (hardening) ve saldırı yüzeyini küçültür.
